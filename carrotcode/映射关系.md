# CPlink 导航数据映射关系完整文档（7706 / CarrotMan）

> **当前产品导航源（三选一）**：**高德地图车机版（广播）**、**腾讯地图（导航 SDK）**、**高德地图手机版（导航 SDK 嵌入）**。  
> 所有模式共用同一条 **UDP 7706** 载荷：App 将 `CarrotManFields` 经 `CarrotManNetworkClient.convertCarrotFieldsToJson()` 序列化为 **UTF-8 JSON**，Comma3 侧 `carrot_man.py` 的 `carrot_man_thread` 接收后调用 **`carrot_serv.update(json_obj)`**（与 `7712/7713` 的 `rgdata` 语义一致）。  
> **OSM 应用内导航已从产品中移除**；文中保留的 OSM/OSRM 表格仅作历史与协议对照，不再代表当前发版行为。  
>
> 图例：✅ 完整可用 | ⚠️ 部分/推断/未接线 | ❌ 无数据（多为默认值）

# 零、7706 JSON 三导航源映射结论（基于代码核对）

## 0.1 发送路径（三导航源一致）

| 步骤 | 说明 |
|------|------|
| 数据源 | 高德车机：`AmapBroadcastHandlers` / `AmapBroadcastManager`；腾讯：`TencentNavDataBridge`；高德手机 SDK 内嵌：`AmapNavDataBridge` + `AmapMobileNavPage`（`AmapNaviPage` / `AmapNaviDataBridge` 为外链车机或未接线参考，勿混淆） |
| 统一模型 | `CarrotManFields`（`CarrotManDataModels.kt`） |
| JSON 构建 | `CarrotManNetworkClient.convertCarrotFieldsToJson()`（**同一套键名**发往 7706） |
| 发送节奏 | `NetworkManager` 约 **200 ms** 调用 `sendCarrotManDataToComma3()` + 差分过滤（`NetworkPerformanceUtils`） |

结论：**三种导航源均已接入 7706 发送链路**；差异在于各源**是否写入** `CarrotManFields` 的字段及映射完整度，而非协议格式不同。

## 0.2 Python `carrot_serv.update()` 实际消费的 JSON 键

以 `carrotcode/carrot/carrot_serv.py` 中 `update(self, json)` 为准：在 **`"nRoadLimitSpeed" in json`** 为真时进入「导航+SDI+TBT」主分支（App 始终 `put("nRoadLimitSpeed", …)`，故该分支会持续执行）。  
另：**`latitude` 等手机 GPS 键**在无导航块或作补充时参与 `update()` 后半段逻辑。

以下字段由 **`convertCarrotFieldsToJson` 发出，但 `update()` 未读取**（仅随 JSON 传输，Comma3 当前逻辑忽略）：`isNavigating`、`nLaneCount`、`tCameraType` / `tCameraDist` / `tCameraSpeedLimit`、`remainingTrafficLights`、`passedDistance` / `passedTime`、`isOnMainRoad`、车道旁车系列键等。

## 0.3 三导航源 vs Python 有效字段 — 总评

| 维度 | 高德车机版 | 腾讯地图 SDK | 高德手机版 SDK |
|------|------------|----------------|----------------|
| **7706 是否发送** | ✅ | ✅ | ✅ |
| **道路限速 `nRoadLimitSpeed`** | ✅ 广播 `LIMITED_SPEED` | ✅ SDK | ✅ `onNaviInfoUpdate` |
| **SDI 类型/距离/限速** | ✅ 完整 `CAMERA_TYPE`→`mapAmapCameraTypeToSdi()` | ✅ `NavCameraType` 等→`TencentNavDataBridge`；区间测速有专门逻辑 | ⚠️ **`updateCameraInfo` + 简化 `mapCameraType`（仅 0~4 粗映射）**，无车机广播级细分与 KEY_TYPE 区间 |
| **区间测速 Block 系列** | ✅ 广播 +  handler | ✅ `NavSpeedMonitorZoneInfo` | ❌ 桥接层未写 `nSdiSection` / Block 动态 |
| **TBT 当前弯** | ✅ `ICON`→`mapAmapIconToCarrotTurn` | ✅ `intersectionType` 等 | ✅ `mapTurnType(iconType)` / 文本兜底 |
| **第二转弯 `nTBTDistNext` / `nTBTTurnTypeNext`** | ✅ 广播字段 | ⚠️ 高德 11.1 `NaviInfo` 无第二 maneuver 字段 | ✅ **`onInnerNaviInfoUpdate`（InnerNaviInfo）→ `AmapNavDataBridge`**（与车机语义仍需路测校准） |
| **`szNearDirName` / `szFarDirName`** | ✅ 广播 | ✅ SDK | ⚠️ **未按近/远端拆分**（当前把 `curRoad`/`nextRoad` 主要写入 `szPosRoadName` / `szTBTMainText`） |
| **位置 `vp*` / `nPos*`** | ✅ 广播车辆位置 | ✅ SDK 道路匹配 | ✅ `onLocationChange`（GCJ→WGS）+ 诱导回调 |
| **目的地 `goalPos*` / `szGoalName`** | ✅ 广播 POI | ✅ 规划结果写入 | ✅ 由导航页/规划写入（与车机同源模型） |

**总结**：三导航源对 **7706 协议层均已「成功映射」**（同一 JSON 出口、Python 可解析）；**语义完整度**以 **高德车机 ≥ 腾讯 > 高德手机** 为主排序——高德手机主要在 **SDI 细分、区间测速、第二转弯、近远端路名** 上弱于前两者的实现深度。

# 三、道路类型 (roadcate) 映射

Python 用途：`roadcate > 1` 时减速带生效；影响 ATC 转弯控制起始距离。`10,11` = 高速公路。

## 3.1 高德 ROAD_TYPE → roadcate

| 高德 ROAD_TYPE | 描述 | roadcate | 说明 |
|---------------|------|---------|------|
| 0 | 高速公路 | 10 | 高速 |
| 6 | 快速道 | 10 | 高速 |
| 1~5, 7~10, else | 国道/省道/县道等 | 6 | 普通道路 |

代码位置：`AmapBroadcastHandlers.kt` → `mapRoadTypeToRoadcate()`

特殊处理：ROAD_TYPE=0/6 且 LIMITED_SPEED=40 时，限速修正为 55km/h（避免堵车误报）。

## 3.2 【历史】OSM highway 标签 → roadcate（产品已移除）

| OSM highway | roadcate | 说明 |
|-------------|---------|------|
| motorway, motorway_link | 1 | 高速公路 |
| trunk, trunk_link | 2 | 城市快速路 |
| primary, primary_link | 3 | 主要道路 |
| secondary, secondary_link | 7 | 次要道路 |
| tertiary, tertiary_link | 7 | 三级道路 |
| residential | 8 | 居民区道路 |
| service | 8 | 服务道路 |
| else | 8 | 默认地方道路 |

代码位置：`OsmDataMapper.kt` → `mapRoadClassToRoadcate()`

数据来源（历史）：Overpass API 查询当前道路的 `highway` 标签。

## 3.3 腾讯导航 → roadcate（推断）

腾讯SDK无直接道路类型API，通过双重推断：

1. **道路名模式匹配**（优先）：
   - 含"高速"/"快速"/"环线"/"高架" 或匹配 `G\d+`/`S\d+` → roadcate=10
2. **限速推断**（回退）：
   - speedLimit ≥ 80 → roadcate=10
   - speedLimit > 0 → roadcate=6
   - 否则保持当前值

代码位置：`TencentNavDataBridge.kt` → `inferRoadcateFromSpeedLimit()`

# 四、道路限速 (nRoadLimitSpeed) 映射

Python 逻辑：`nRoadLimitSpeed <= 0` → 设为30；`> 200` → `(val-20)/10`；`== 120` → 115

- 来源：`LIMITED_SPEED` 广播字段
- 特殊修正：ROAD_TYPE=0/6 且 LIMITED_SPEED=40 → 强制 55km/h

- 回退：按道路等级默认值

| motorway, motorway_link | 120 |
| trunk, trunk_link | 80 |
| primary, primary_link | 60 |
| secondary, secondary_link | 50 |
| tertiary, tertiary_link | 40 |

| service | 20 |

代码位置：`OsmDataMapper.kt` → `getDefaultSpeedLimit()`

## 4.3 腾讯 → nRoadLimitSpeed

- 来源：SDK `getLimitSpeed()` / `getCurrentSpeedLimit()` 反射探测

## 十三（附）、高德手机内嵌导航扩展说明（SDK 11.1.200）

| 能力 | 实现要点 |
|------|----------|

| 全览 | `displayOverview()` / `recoverLockMode()` + `isRouteOverviewNow()` |

| 策略 UI | 自研 BottomSheet → `strategyConvert` + 导航中 `reCalculateRoute(strategy)`；**勿**在无隔离宿主下打开 `setShowRouteStrategyPreferencePanel(true)` |

### 真机回归清单（高德手机内嵌）

1. 冷启动进入内嵌导航：默认车头向上、无崩溃。  
2. 多备选出现：切换路线 ID，摘要（km/min）合理。  
3. 全览 ↔ 跟车：`recoverLockMode` 恢复锁车。  
4. 并行路回调后 HUD 字段变化；主路/辅路按钮可点。  
5. 打开「显示」中鹰眼/路口大图等：无崩溃；无套餐时应有 Toast 或静默失败。  
6. 「策略」应用后：导航中触发重算，路线刷新且导航不中断。  
7. 偏航/拥堵重算（自然触发）：`routeSuccessOnce` 不重复 `startNavi`。
