# 零、7706 JSON 三导航源映射结论（基于代码核对）

```
App 导航 SDK → CarrotManFields → CarrotManNetworkClient.convertCarrotFieldsToJson()

```

# 四、道路限速 (nRoadLimitSpeed) 映射

## 4.1 高德 -> nRoadLimitSpeed

高德 AMap 通过 `onUpdateNaviSpeedLimitSection` 回调提供限速序列，直接取 `nRoadLimitSpeed`。

**实际限速来源优先级**（`update_navi` 中）：
1. `CS.speedLimit`（cereal 限速）> 0 且 `active_carrot <= 1` -> 覆盖
2. `nRoadLimitSpeed`（来自手机 JSON）
3. App 发送的 `nRoadLimitSpeed` 经过防抖 + 纠偏（`nRoadLimitSpeed_counter > 5`）

## 4.2 【历史】OSM -> nRoadLimitSpeed（产品已移除）

| OSM maxspeed 来源 | 优先级 |
|------------------|:------:|
| OSM 路网 maxspeed 标签 | 高 |
| App 限速标志识别结果 | 低 |

## 4.3 腾讯导航 -> nRoadLimitSpeed

腾讯 SDK 通过 `onUpdateNaviSpeedLimitSection` 回调返回 `speedLimit` 列表，取最近一段限速值。

# 五、交通灯（TrafficLight -> sinf）

**⚠️ 当前 App (CPlink) 不发送 `sinf` 包。** 7712/7713 端口的 `sinf` 由外部第三方系统发送。

## 5.1 `handle_traffic_light` 转换（车机 Python）

| sinf 字段 | 类型 | Python 处理 |
|----------|------|------------|
| `redLightOn` | boolean | 优先级最高 |
| `leftLightOn` | boolean | 次高 |
| `greenLightOn` | boolean | 第三 |
| `rightLightOn` | boolean | 第四 |
| `uturnLightOn` | boolean | 最低 |
| `*RemainTime` | int | 对应灯的剩余秒数 |
| `distance` | int | 距路口距离（米） |

**输出**：`params_memory["TrafficLight"]` = `{"distance": int, "lamp": str, "remain": int}`

## 5.2 【历史】原 OSM 模式 — 交通灯（产品已移除）

原 `carrot_serv.py` 内置基于坐标的虚拟交通灯管理逻辑（`traffic_light()` 方法），已不再使用。

## 5.3 腾讯模式 — 交通灯

腾讯 `TencentNaviManager` 从回调数据提取交通灯信息，使用 `sendPacket(flag=TRAFFIC_SIGNAL, data=json)` 通过 UDP 发送。由于当前 CPlink 架构改为走 7706 JSON，此路径已不活跃。
