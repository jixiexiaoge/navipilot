# UART通信协议规范

本部分描述蓝牙IC与屏幕之间通信所使用的`uart`协议规范

![](./assets/payload.png)

## 约定

### 字节序
本协议所描述的数据传输在物理层以 **MSB-First**(高位在前) + **Little-Endian**(小端序) 的格式进行

### 数字表示
> 在本文档中:  
> 形如 `13` 的无前缀数字表示十进制数  
> 形如 `0x13` 的以 `0x` 为前缀的数字表示十六进制数  
> 形如 `0b11011011` 的以 `0b` 为前缀的数字表示二进制数

## 数据帧

数据帧为每次uart传输的最小有效单位，一个数据帧的结构如下所示，每帧数据最多可以包含`242`字节的有效载荷

| 序号 |       内容       |               备注               |
| :--- | :--------------- | :------------------------------- |
| 0    | `0x5E`           | 固定前缀                         |
| 1    | $A_1$            | 随机数                           |
| 2    | $A_0\oplus A_1$  | 固定前缀与随机数的异或值         |
| 3    | Length           | 载荷长度                         |
| 4    | $A_2 \oplus A_3$ | 异或校验值                       |
| 5~n  | Payload          | 载荷                             |
| n+1  | CheckSum         | 校验和 = $\sum_5^n A_n \oplus n$ |

其中，使用 $A_n$ 表示一个数据帧中的第 `n` 个 `byte`，例如，首个字节为 $A_0 = \tt{0x5E}$ 为固定前缀。

### 载荷

载荷为需要实际传输的二进制内容

| 序号 |         内容         |                            备注                             |
| :--- | :------------------- | :---------------------------------------------------------- |
| 5    | `0xCD`,`0xDA`,`0xE0` | 载荷类型<br>`0xCD` = 命令<br>`0xDA` = 数据<br>`0xE0` = 报错 |
| 6~7  | `0x0000`~`0xFFFF`    | `CUID`（16位循环唯一ID）                                    |
| 8~n  | Content              | 载荷内容                                                    |

载荷的第一个字节为 $A_5$，表示载荷的类型。`命令`类型表示当前载荷内容的含义是完全自解释的，而`数据`类型的载荷表示其内容需要根据上下文来解释。`报错`类型用于返回一个[错误](#错误)。

`CUID`用于传输的流控和确认机制。在无特殊说明时，每发送一帧数据时将`CUID`加一即可。发送确认时，根据`CUID`即可完成唯一确认。

`CUID`的详细使用方式后有详述。

#### 命令

命令载荷的内容根据16位命令的内容即可完整解析

| 序号 |       内容        |   备注   |
| :--- | :---------------- | :------- |
| 8~9  | `0x0000`~`0xFFFF` | 16位命令 |
| 10~n |                   | 命令内容 |

#### 数据

数据载荷的内容需要结合上下文解析

| 序号 | 内容 |   备注   |
| :--- | :--- | :------- |
| 8~n  |      | 数据内容 |

### ACK

当载荷长度为`3`，即载荷不包含任何内容，只包含类型与`CUID`时，表示这是一个`ACK`，向对方确认已经收到了对应类型对应`CUID`的数据帧。

**协议内容**
| 序号 |       内容        |              备注              |
| :--- | :---------------- | :----------------------------- |
| 5    | `0xCD` or `0xDA`  | `0xCD` = 命令<br>`0xDA` = 数据 |
| 6~7  | `0x0000`~`0xFFFF` | `CUID`（16位循环唯一ID）       |

蓝牙端下行传输未及时收到`ACK`时，将重发一次


### 错误

当命令无法完成或得到期望结果以外的结果时，使用`错误`类型返回一个16位错误码。

**协议内容**
| 序号 |       内容        |           备注           |
| :--- | :---------------- | :----------------------- |
| 5    | `0xE0`            | 载荷类型：报错           |
| 6~7  | `0x0000`~`0xFFFF` | `CUID`（16位循环唯一ID） |
| 8~9  | error_code        | 错误码                   |

#### 错误码

| 错误码 |       含义       |
| :----- | :--------------- |
| `400`  | 无效的命令或参数 |
| `401`  | 来源未认证       |
| `402`  | 访问无权限       |
| `404`  | 访问的资源不存在 |
| `408`  | 处理超时         |
| `409`  | 状态冲突         |
| `413`  | 内容过大         |
| `415`  | 不支持的格式     |
| `428`  | 版本过期         |
| `429`  | 重复请求         |
| `500`  | 内部错误         |
| `503`  | 当前忙，无法处理 |
| `505`  | 版本不兼容       |

在定义的错误码中，一部分是通用的报错，比如在命令载荷中解析到一个未定义的命令，那么就会返回 `400` 错误，使用资源指纹请求的资源不存在时，返回 `404` 错误等。

在可能会有错误码返回的协议中，将会明确表示在何种情况下应该返回何种错误码。
