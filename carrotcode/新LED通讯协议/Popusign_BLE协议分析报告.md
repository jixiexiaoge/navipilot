## 2. 协议分层

```
┌─────────────────────────────────────────────┐
│  应用层协议 (screen2app.md 定义)             │
│  ┌───────────────────────────────────────┐   │
│  │ 命令/数据载荷: [type][cuid][content] │   │
│  └───────────────────────────────────────┘   │
├─────────────────────────────────────────────┤
│  传输层 UART 帧 (通信协议规范.md 定义)       │
│  ┌───────────────────────────────────────┐   │
│  │ 0x5E 帧: [0x5E][rand][xor][len][crc] │   │
│  └───────────────────────────────────────┘   │
├─────────────────────────────────────────────┤
│  物理层: BLE / UART                          │
│  BLE: WRITE_CMD(0x52) + NOTIFY(0x1B)         │
│  UART: 蓝牙IC ↔ 屏幕 MCU                     │
└─────────────────────────────────────────────┘
```

BLE 抓包中 **没有 0x5E 帧头** — 蓝牙IC与手机通信时自动剥离/添加, 应用层只需发送裸载荷。

## 3. BLE 连接与广播

### GATT 服务

| Handle | 属性 | UUID | 用途 |
|--------|------|------|------|
| `0x0003` | WRITE_CMD | `0000a802-0000-1000-8000-00805f9b34fb` | App→屏幕 |
| `0x0005` | NOTIFY | `0000a801-0000-1000-8000-00805f9b34fb` | 屏幕→App |
| `0x0006` | CCCD | — | Notification 启用 |

### 连接参数

| 参数 | 值 |
|------|-----|
| MTU | 247~512 |
| Write 类型 | WRITE_NO_RESPONSE |
| 写入特征 | TX (`a802`) |
| 通知特征 | RX (`a801`) |

### 广播参数 (来自 181410)

| 参数 | 值 |
|------|-----|
| BLE 名称 | 机械小鸟 |
| 广播类型 | LE Extended Advertising (Legacy) |
| 广播属性 | Scannable + Directed |
| 最小间隔 | 162ms (259 × 0.625ms) |
| 最大间隔 | 2.73s (4370 × 0.625ms) |
| 主通道 PHY | LE 1M |

## 4. BLE 帧格式

写入和通知使用相同的格式, **没有前导 0x00 字节**:

```
[seq(1B)] [remaining_len(1B)] [payload...]
```

payload 格式 (与 UART 0x5E 协议的载荷一致):

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 0 | 1 | type | `0xCD`=命令, `0xDA`=数据, `0xE0`=错误 |
| 1-2 | 2 | cuid (LE16) | 循环唯一ID, 流控确认用 |
| 3~n | 可变 | content | 命令参数或数据内容 |

> UART 帧头 (`0x5E`, 随机数, 异或值, 长度, 校验和) 由蓝牙IC内部处理, APP 只需发送裸载荷。

---

## 5. 载荷类型

### 命令 (type=0xCD)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 3-4 | 2 | command (LE16) | 16位命令码 |
| 5~n | 可变 | args | 命令参数 |

### 数据 (type=0xDA)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 3~n | 可变 | content | 数据内容 (依赖上下文解析) |

### 错误 (type=0xE0)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 3-4 | 2 | error_code (LE16) | 错误码 |

## 6. ACK 与流控

当 payload 长度为 3 (只有 type + cuid, 无 content) 时表示 ACK, 确认收到对应 type + cuid 的数据帧。

下行未及时收到 ACK 时, 将重发一次。

### 错误码

| 错误码 | 含义 |
|--------|------|
| 400 | 无效的命令或参数 |
| 401 | 来源未认证 |
| 402 | 访问无权限 |
| 404 | 访问的资源不存在 |
| 408 | 处理超时 |
| 409 | 状态冲突 |
| 413 | 内容过大 |
| 415 | 不支持的格式 |
| 428 | 版本过期 |
| 429 | 重复请求 |
| 500 | 内部错误 |
| 503 | 当前忙, 无法处理 |
| 505 | 版本不兼容 |

## 7. NOTIFY 响应格式

屏幕→App 的通知(NOTIFY)使用与 WRITE 相同的载荷格式:

```
[seq(1B)] [remaining_len(1B)] [type=0xCD(1B)] [cuid(2B LE)] [content...]
```

NOTIFY 的 type 始终为 `0xCD`(命令), content 格式:
```
[cmd_echo(2B LE)] [response_data...]
```

- `cmd_echo`: 被响应的命令码 (如 D702 响应内容以 `02 D7` 开头)
- `response_data`: 依赖具体命令的响应数据

### 常见 NOTIFY 响应

| 响应 | 内容格式 | 说明 |
|------|---------|------|
| D702 设备信息 | `02 D7 [pad(2B)] [model(8B)] [id...]` | 型号如 `20 20 47 4C 31 36 39 36 48` = "  GL1696H" |
| D602 节目列表 | `02 D6 [count(4B LE)] [更多...]` | 节目数量 |
| 0A01 播放状态 | `01 0A [type(1B)] [group(1B)] [prog(1B)] [uuid(6B)] [more...]` | type=`0x41`=全部循环, `0x53`=单节目 |
| C002 参数读取 | `02 C0 [TLV_params...]` | TLV 格式参数列表 |
| C081 状态通知 | `81 C0 80 [state(1B)] [group(1B)] [prog(1B)] [uuid(6B)]` | state=`0x01`=播放 |

空响应 (无 content) 表示纯 ACK / 命令已接收。

## 9. 关键命令详解

### 9.1 显示开关 (0xE01)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 5 | 1 | on/off | `0x00`=关, `0x01`=开 |

### 9.2 亮度调节 (0xE02)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 5 | 1 | level | `0x00`~`0xFF` |

### 9.3 播放控制 (0x0A01)

**全部循环:**
```
args: [CMD(1B)] [LOOP=0x41] [groups...]
```
- CMD: `0x00`=暂停, `0x01`=播放
- LOOP: `0x41`=全部循环
- groups: 参与循环的节目组序号列表

**单个循环:**
```
args: [CMD(1B)] [LOOP=0x53] [group(1B)] [program(1B)] [pad(1B)]
```
- CMD: `0x00`=暂停, `0x01`=播放
- LOOP: `0x53`=单个循环
- group: 节目组序号
- program: 节目序号

**读取播放参数:**
```
args: [CMD=0xEA]
```

**播放状态上传** (屏幕→App, 0x0A01 作为上行):
```
[playType(1B)] [group(1B)] [program(1B)] [uuid(6B)] [N(1B)] [groups...]
```
- playType: `0x41`=全部循环, `0x53`=单个循环
- uuid: 当前播放资产

**已验证的工作参数** (从抓包提取):
| 功能 | args | 说明 |
|------|------|------|
| 全部循环 | `01 41 00` | 从组0开始全部循环 |
| 单节目循环(组0节目0) | `01 53 00 00 00` | 组0节目0, 末字节填充 — 上传前清空显示 |
| 单节目循环(组1节目0) | `01 53 01 00 00` | 组1节目0, 上传后切换到新节目 |
| 读取播放参数 | `EA` | 用于查询当前播放状态 |

> 注意1: 实测必须在全部循环后发单节目循环才能生效。
> 注意2: `01 53 00 00 00` 可在资产上传前用于暂停当前播放；`01 53 01 00 00` 在上传完成后切换生效。

### 9.4 节目编辑 (0xED01)

```
args: [group(1B)] [program(1B)] [sub_count(1B)] [sub_elements...]
```

子元素格式 (type=0x00, 资产引用):
```
[type(1B)=0x00] [padding(7B)=0x00] [uuid(6B)]
```

节目组中未填充的子元素数量置为0。

### 9.5 资产下载 (0xD001)

```
args: [length(4B LE)] [start_cuid(2B LE)] [uuid(6B)]
```

| 字段 | 大小 | 说明 |
|------|------|------|
| length | 4B LE | 资产总字节数 |
| start_cuid | 2B LE | 后续 DATA 帧起始 CUID |
| uuid | 6B | 资产唯一标识 |

**传输流程** (官方规范):
```
App                    Screen
 |                        |
 |--- D001 (请求下载) ---->|
 |<-- ACK ----------------|   (1秒内)
 |--- DATA ×N (分片) ---->|   每帧244B, 每页500帧
 |<-- 页ACK --------------|   (每页完成)
 |--- DATA ×N (下一页) --->|
 |<-- 页ACK --------------|
 |--- DATA ACK (完成) ---->|
 |--- ED01 (节目编辑) ---->|   ← ED01 在 C081 之前发送，无需等待通知
 |<-- C081 (通知) --------|   (含资产UUID, 图片解码完成通知)
```

**实际抓包验证流程** (2026-06-05 自定义文字上传):
```
App                                        Screen
 |                                           |
 |--- 0A01 01 53 00 00 00 (预置单节目) ---->|
 |--- D001 (资产下载请求) ------------------>|
 |<-- NOTIFY ACK (空帧, 确认接收) ----------|
 |--- DATA ×N (数据分片) ------------------->|   每个DATA帧独立UUID
 |--- DATA ACK (空帧, cuid=0) -------------->|
 |--- ED01 (节目编辑: 引用UUID) ------------>|
 |<-- C081 (通知: 含资产UUID, 图片解码完成) -|
 |--- 0A01 01 53 01 00 00 (切换到新节目) --->|
```

> 小资产(<750B)直接单页完成, 无分页逻辑。上传前需设置播放模式, 上传后需显式切换到新节目。

**DATA 帧分片结构**:
每个资产上传请求(D001)后跟多个 DATA 帧, 每个 DATA 帧有独立格式:
```
[UUID(6B)] [type(1B)] [payload...]
```
- **第一帧**: UUID 与 D001 请求的 UUID 一致, type=0x01, 包含结构化文本布局
- **后续帧**: UUID 不同(可能是连续数据块), type 为 0x63/0xC0/0x18 等, 含后续位图数据
- **结束帧**: DATA 空帧 (cuid=0), 表示传输完成

> 注意: DATA 帧的 UUID 与 D001 的 UUID 不完全相同 — D001 的 UUID 标识资产, DATA 帧的 UUID 标识数据块。

### 9.6 设备状态控制 (0xC001)

```
args: [CMD(1B)] [STATE(1B)] [params...]
CMD: 0x00=获取, 0x01=设置
```

| STATE | 名称 | 说明 |
|-------|------|------|
| 0xFF | 开机 | 无参数 |
| 0x01 | 节目播放 | 参数: [group][program][uuid(6)] |
| 0x02 | 节目预览 | 参数: [uuid(6)] |
| 0x03 | 涂鸦(Doodle) | 无参数 |

**已验证参数**:
- 开机: `01 FF`
- 涂鸦模式: `01 03`
- 节目播放: `01 01` (退出涂鸦, 进入播放模式)

### 9.7 设备状态通知 (0xC081)

```
content: [CMD=0x80] [STATE(1B)] [params...]
```

示例: `80 01 02 01 AABBCCDDEEFF` 表示节目播放状态, 组2, 节目1, UUID=AABBCCDDEEFF。

**抓包验证** (NOTIFY content):
```
81 C0 80 01 00 00 CC 29 FA 34 00 30
```
- `81 C0` = 0xC081 命令回显 (NOTIFY 格式)
- `80` = CMD 字节
- `01` = 节目播放状态
- `00` = 组0
- `00` = 节目0
- `CC 29 FA 34 00 30` = 当前播放资产 UUID

上传完成后 C081 会携带新资产的 UUID 通知图片解码完成。

### 9.8 设备参数控制 (0xC002)

```
args: [CMD=0x00获取/0x01设置] [params...]
```

**获取全部参数** (CMD=0x00):
```
args: 00
```

设备响应为 TLV 格式:
```
[echo_cmd=0xC002(2B LE)] [TLV_params...]
```

| 参数类型 | 类型值 | 字节 | 说明 |
|---------|--------|------|------|
| 屏幕旋转 | 0x01 | 1 | Value×90° |
| 定时关机 | 0x02 | 2 | 倒计时分钟, 0=取消 |
| 密码 | 0x03 | N | 密码字符串 |
| 屏幕开关 | 0x04 | 1 | 0=关, 非0=开 |
| 亮度 | 0x05 | 1 | 亮度值 |

**抓包验证格式** (C002 00 读取响应):
```
02 C0 02 01 00 03 02 00 00 02 04 01 02 05 FF
```
解析: `02 01 00` = 旋转=0 (type=02=1B值), `03 02 00 00` = 定时关机=0 (type=03=2B值),
`02 04 01` = 屏幕=开, `02 05 FF` = 亮度=255

### 9.9 实时显示 — 快速绘制 (涂鸦模式)

**实色填充 (0xD517):**
```
args: [COLOR(2B LE)] [shape(1B)=0x00] [X(2B LE)] [Y(2B LE)] [W(2B LE)] [H(2B LE)]
```
- shape: `0x00`=矩形
- COLOR: RGB565

**全局颜色多点 (0xD507):**
```
args: [COLOR(2B LE)] [X0(2B LE)] [Y0(2B LE)] [X1(2B LE)] [Y1(2B LE)]...
```

**独立像素着色 (0xD508):**
```
args: [X0(2B LE)] [Y0(2B LE)] [COLOR0(2B LE)] [X1(2B LE)] [Y1(2B LE)] [COLOR1(2B LE)]...
```

### 9.10 设备系统控制 (0xC055)

```
args: [CMD=0x01] [command]
```
- `0xF1`=重启, `0xF2`=清空节目, `0xFE`=格式化Flash

### 9.11 设备信息上传 (0xD702)

```
content: [cmd=0xD702] [model(8B)] [id(8B)] [version(3B)] [width(2B LE)] [height(2B LE)] [direction(1B)] [memory(4B)] [memory_free(4B)]
```

### 9.12 产线测试 (0x0F01)

```
args: [TYPE(1B)]
```
- `0x00`~`0x07`: 纯色 (红绿蓝黄青紫白黑)
- `0x10`: 行条纹
- `0x11`: 列条纹
- `0x12`: 格子

## 10. 协议工作流

### 10.1 启动流程

```
APP                                     屏幕
 |                                        |
 |--- BLE 连接 + MTU 协商 --------------->|
 |--- 启用 Notification (写CCCD) -------->|
 |                                        |
 |--- C001 01 FF (开机) ----------------->|
 |--- 0E02 FF (亮度) -------------------->|
 |--- 0E01 01 (显示开) ------------------>|
 |--- C001 01 03 (涂鸦模式) -------------->|
 |                                        |
 | (可选: 查询设备信息/节目列表/参数)      |
 |--- D702 00 (获取设备信息) ------------->|
 |<-- D702 (设备信上传) ------------------|
 |--- D602 00 (获取节目列表) ------------->|
 |<-- D602 (节目列表上传) ----------------|
 |--- 0A01 EA (读取播放参数) ------------->|
 |<-- 0A01 (播放状态上传) ----------------|
```

### 10.2 资产上传 → 文字显示

#### 完整流程 (2026-06-05 抓包验证)

实际抓包显示, 自定义文字上传分为三个阶段:

**阶段1: 查询设备状态** (App 启动后)
```
APP                                       屏幕
 |                                           |
 |--- D702 00 (获取设备信息) ---------------->|
 |<-- D702 RSP (型号 GL1696H, 版本, 内存) ---|
 |--- D602 00 (获取节目列表) ---------------->|
 |<-- D602 RSP (节目数, 列表) ---------------|
 |--- 0A01 EA (读取播放参数) ---------------->|
 |<-- 0A01 RSP (当前播放模式, UUID) ---------|
 |--- C002 00 (读取设备参数) ---------------->|
 |<-- C002 RSP (旋转, 定时关机, 屏幕, 亮度) -|
 |<-- C081 (播放状态通知) -------------------|
```

**阶段2: 资产上传** (发送文字内容)
```
APP                                       屏幕
 |                                           |
 |--- 0A01 01 53 00 00 00 (单节目循环) ---->|  预置空节目, 暂停当前播放
 |--- D001 [len] [start_cuid] [uuid] ------->|  资产上传请求
 |<-- NOTIFY ACK (空帧) --------------------|
 |--- DATA ×N (数据分片) ------------------->|  含 UUID + type + payload
 |--- DATA ACK (cuid=0 空帧) --------------->|  传输完成标识
 |--- ED01 [group=0] [prog=0] [uuid] ------->|  节目编辑: 引用资产 UUID
 |<-- C081 (通知: UUID, 图片解码完成) -------|
 |--- 0A01 01 53 01 00 00 (切换新节目) ---->|  切换到组1节目0 生效
 |<-- NOTIFY ACK ---------------------------|
```

> **注意**: 上传前 `0A01 01 53 00 00 00` 先锁定空节目(组0节目0)暂停播放;
> 上传后 `0A01 01 53 01 00 00` 切换到组1节目0使新内容可见。
> 无需 `C001 01 01` 退出涂鸦模式 — 该命令适用于从实时绘制切回节目模式。

**阶段3: 重复上传 (覆盖同一节目槽)**
```
--- D001 [新UUID] ------------------------->|
--- DATA ×N ------------------------------->|
--- ED01 [group=0] [prog=0] [新UUID] ------>|  覆盖同一节目槽
--- 0A01 01 53 01 00 00 (切换生效) -------->|
```

#### 快速流程 (官方 APP, 单次上传)

```
APP                                     屏幕
 |                                        |
 |--- C001 01 01 (退出涂鸦模式) ---------->|
 |--- D001 (资产下载请求) ----------------->|
 |<-- ACK (确认接收) ---------------------|
 |--- DA×N (数据分片) -------------------->|
 |--- DA CUID=0 (结束ACK) ---------------->|
 |<-- C081 (通知: UUID确认) --------------|
 |--- ED01 (节目编辑: 引用UUID) ---------->|
 |--- 0A01 01 41 00 (全部循环播放) -------->|
 |--- 0A01 01 53 01 00 00 (单节目循环) ---->|
```

### 10.3 涂鸦模式实时填充

```
APP                                     屏幕
 |                                        |
 |--- C001 01 03 (涂鸦模式) -------------->|
 |--- D517 (实色填充) -------------------->|
 |--- D507/D508 (快速像素绘制) ----------->|
 |                                        |
 | (保活: 定期重发涂鸦内容防止切回轮播)    |
```

### 10.4 长数据传输通用流程 (官方规范)

适用于: D001资产下载, D501实时显示, D602节目列表上传, D002资产上传, D582显示上传

```
App                                    Screen
 |                                        |
 |--- 请求帧 (命令+长度+起始CUID) ------->|
 |<-- ACK (确认接收) ---------------------|
 |--- DATA ×500 (单页分片) -------------->|
 |<-- 页ACK (每页完成) ------------------|
 |--- DATA ×N (剩余页) ------------------>|
 |<-- 完成ACK ----------------------------|
```

- 单帧有效载荷: 244 字节
- 单页承载: 500 帧
- 1秒未ACK → 链路心跳
- CUID 断序 → 整页重传

## 11. 资产数据格式 (结构化文本布局)

基于官方 APP 抓包逆向分析。a800 不接受原始位图, 使用结构化文本布局格式。

资产数据在 BLE DATA 帧中传输, 分片结构:
```
BLE DATA 帧内容:
  [chunk_uuid(6B)] [chunk_type(1B)] [chunk_payload...]
```

- **第一帧**: `chunk_uuid` = D001 请求的 UUID, `chunk_type=0x01`, 包含完整资产头部
- **后续帧**: `chunk_uuid` 为连续数据块的标识(非 D001 UUID), 包含剩余位图数据
- 所有 DATA 帧的 `chunk_payload` 按序拼接为该资产的完整数据

### 11.1 整体结构

```
asset_bytes (首个 DATA 帧的 chunk_payload):
  [prefix(62B)] [text_section] [BE32_charCount] [pad(1B)] [xpos_table] [char_glyphs...]
```

### 11.2 前缀格式 (62B)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 0 | 17 | header | `00 0C` + 15个零 |
| 17 | 6 | embedded_uuid | 资产UUID前4B + `00 00` |
| 23 | 2 | marker | `54 00` (固定标识) |
| 25 | 4 | var1 (LE32) | 资产总字节数 - 32 |
| 29 | 4 | var2 (LE32) | `0x38 + (字数-1)×4` |
| 33 | 8 | sub_anim | `02 00 02 00 02 00 03 XX` |
| 41 | 16 | sub_text_settings | `02 00 11 04` + `02 00 10 01` + `02 00 12 01` + `02 00 20 00` |
| 57 | 3 | color_header | `03 00 21` |
| 60 | 2 | color (RGB565) | 颜色值 (见下方) |

**var1 公式**: `var1 = 7 (UUID) + 1 (type) + 62 (prefix) + text_section_size + 4 (BE32) + 1 (pad) + glyphCount×4 (xpos) + glyphCount×36 (glyph) - 32`

> 公式中的 -32 是基于官方抓包的固定偏移量。

**var2 公式**: `var2 = 0x38 + (glyphCount - 1) × 4`

#### 颜色 (RGB565, prefix[60-61] LE)

RGB565: R(5高位) G(6位) B(5低位)

| 颜色 | 字节 (LE) | RGB565 | 分解 |
|------|-----------|--------|------|
| 红 | `00 F8` | 0xF800 | R=31 G=0 B=0 |
| 绿 | `E0 07` | 0x07E0 | R=0 G=63 B=0 |
| 蓝 | `1F 00` | 0x001F | R=0 G=0 B=31 |
| 青 | `FF 07` | 0x07FF | R=0 G=63 B=31 |
| 黄 | `E0 FF` | 0xFFE0 | R=31 G=63 B=0 |
| 紫 | `1F F8` | 0xF81F | R=31 G=0 B=31 |
| 白 | `FF FF` | 0xFFFF | R=31 G=63 B=31 |

#### 动画 (prefix[40])

| 值 | 效果 |
|----|------|
| 0x00 | 静态 |
| 0x23 | 左移 |
| 0x21 | 右移 |
| 0x42 | 闪烁 |

### 11.3 文本段

紧随前缀:

```
02 00 22 00           -- 文本段起始
02 00 23 02           -- 文本方向 (0x02=横排)
02 00 24 00           -- 文本内容标记
[len_LE]              -- UTF-8文本长度+1 (含2A前缀)
2A                    -- 固定前缀
[UTF-8 bytes]         -- 文本内容
02 00 2B 10           -- 字间距 (0x10=16)
02 00 2C 01           -- 对齐 (0x01=居中)
00                    -- 分隔符
```

### 11.4 字符数与位置表

```
[BE32 charCount]      -- 大端序字符数 (4B)
[pad=0x00]            -- 填充 (1B)
[xpos_table...]       -- 每字4B LE32: 指向该字在payload中的偏移
```

xpos 公式: `offset = entriesStart + index × 36 - 17`
其中 `entriesStart = 62 + textSectionSize + 4 + 1 + glyphCount × 4`

### 11.5 逐字字型

每个字固定 36B:

```
[10 00] [10 00] [32B 列优先位图]   -- cell_w=16(LE), cell_h=16(LE), 位图(16列×2B)
```

**注意**: 官方格式没有 `fmt` 和 `render_w` 字段！位图包含全部 16 列的像素数据。
之前版本错误地添加了 `[03 00]` (fmt) 和 `[0E 00]` (render_w=14) 字段，
导致设备将 4 字节错读为像素数据，显示完全乱码。

位图格式: 每列2字节, 上半行低位→高位, 下半行低位→高位, 16列共32B。

## 12. 与官方规范的差异

### 12.1 BLE 帧头

| 方面 | 官方 UART 规范 | BLE 抓包 |
|------|---------------|----------|
| 帧头 | `0x5E` + rand + xor + len + crc | 无 (蓝牙IC处理) |
| 载荷格式 | `[type][cuid][content]` | 相同 |
| ACK | 载荷长度=3, 无 content | 相同 |

### 12.2 播放控制格式

| 功能 | 官方规范格式 | 抓包验证格式 |
|------|-------------|-------------|
| 全部循环 | `[CMD][0x41][groups...]` | `01 41 00` ✓ |
| 单个循环 | `[CMD][change][0x53][group][program]` | `01 53 01 00 00` (无显式 change 字节) |

> 抓包格式可能省略了 change 字段, 或使用不同版本格式。已验证工作参数: `01 53 01 00 00`。

### 12.3 资产下载流程

| 方面 | 官方规范 | 抓包验证 |
|------|---------|----------|
| 分页 | 500帧/页 + 页级ACK | 无分页, 直接传完 |
| 单帧载荷 | 244B | 153B (受MTU=247限制, 帧头开销后实际可用) |
| 完成确认 | 页ACK+完成ACK | DATA CUID=0 空帧 |
| 上传前准备 | (无) | `0A01 01 53 00 00 00` 锁定空节目暂停播放 |
| 上传后生效 | (无) | `0A01 01 53 01 00 00` 切换到新节目 |

> 小资产(<750B)直接单页完成, 大资产可能才触发分页逻辑。
> 新发现的上传流程包含上传前预置和上传后切换两个额外步骤, 官方 APP 流程中未见此步骤。

### 12.4 设备查询流程

| 方面 | 官方规范 | 抓包验证 |
|------|---------|----------|
| 启动/连接后 | C001 开机 → 0E02 亮度 → 0E01 显示 → C001 涂鸦 | D702/D602/0A01/C002 设备查询序列 |
| C002 用途 | 设置参数(带参数类型和值) | 也用于读取全部参数(CMD=0x00) |

> 对于已开机的设备, App 连接后先查询设备信息/节目列表/播放状态/参数, 而非执行启动序列。
> C002 可通过 `C002 00` 一次读取所有参数, 以 TLV 格式返回。

### 12.5 实时显示 vs 资产

| 路径 | 用途 | 优势 |
|------|------|------|
| 资产上传 (D001→DATA→ED01) | 持久化文字/图片 | 断电保持, 节目管理 |
| 涂鸦绘制 (D517/D507/D508) | 临时画面 | 低延迟, 适合实时更新 |
| HCI FD57 (Qualcomm 厂商命令) | 直接写扫描线 | 更低延迟, 绕过GATT栈 |

|------|------|-----------|
| 0x02 | 1字节值 | 1B |
| 0x03 | 2字节值 | 2B LE |
| 0x04 | 4字节值 | 4B LE |
