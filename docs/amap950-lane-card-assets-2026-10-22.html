可移植78 张车道 / 转向箭头

其中 13 张双车道推荐箭头（白=本车道、蓝=推荐车道）才是车道卡片的视觉本体；其余是单箭头模板、变道箭头与车道分隔线。

半移植卡片外框是 shape XML

custom_card_suspension_card_nav_* 这类圆角/渐变背景是 XML 矢量，不是位图，照参数重画即可。

拿不到2DCross / 3DCross 路口放大图

包内只有互斥规则（guide_card_rule.dat），没有任何位图。放大图由 native 引擎按地图矢量数据实时绘制。

2 · 核心发现：车道卡片就是这 13 张

看图就明白：高德把「本车道 + 推荐车道」画进了同一张 53×70 的图里 —— 白色箭头是本车道，蓝色箭头是推荐车道。 这就是导航时那张车道卡片的视觉本体，不是引擎现画的，可以直接移植。

编号 1 / 21 / 43 / 63 / 73 / 95 / 105 / 121 / 130 / 141 / b1 / c8 / e5 与 navistate_landfront 同源 —— 高德 TD ICON 编号体系。

6 · 引擎侧：为什么放大图拿不到

libMapAsset.so
12.7 MB，自定义包 MapAsset v.1.0.0.1，内含 47 张 PNG，全是 2048×1024 / 544×1264 这类地图贴图，与车道卡片无关
libLayerAsset.so
4.3 MB，图层样式资源
lane_navi_config.bin
21 KB，引擎车道绘制调参：minDistanceCanZoominFreeway、maxSurfaceLength、showNearAnchorDistance、occupySpecialLaneCanDrawRegion —— 车道面由引擎按参数实时生成
2DCross / 3DCross
全包搜索只命中 guide_card_rule.dat（规则），无图片、无布局

7 · 移植建议（本次未动 app 代码）

  1. 方案 A（推荐）：直接复用位图。把 global_landfront_recommend_* 13 张放进 res/drawable-nodpi，按车道数横向排布即可拼出车道卡片；单箭头态用 navistate_landfront_* + ColorFilter tint。
  2. 尺寸：原图 53×70，3 车道卡片高 ≈ 70dp、每车道 ≈ 53dp；超过 5 车道应整体缩放，不要继续横向拼接。
  3. 背景：卡片外框用 shape XML 重画（圆角 + 纵向渐变 + 1px 描边），参数可从 custom_card_suspension_card_nav_* 反查 dimens/color。
  4. 不要复刻 2DCross：那是 3D 引擎按地图 mesh 画的，投入产出不划算；需要路口图就自己用 Compose Canvas 画示意。
