左侧路口放大图：引擎矢量绘制，不是图片

云端下发一段矢量描述，bl::VectorCrossLayerItem::ShowVectorCross(const uint8_t*, int) 接进来， 引擎按 GuideConfig.json 的路宽 / 贝塞尔 / 箭头参数实时画。部分路口换成实景图（CrossImageInfo + SegmentInfo::HasCrossImage()）。

右侧车道箭头卡：位图按车道拼

数据是高德广播的 drive_way_lane_Back_icon（0–12）+ 推荐标志； 图是包里那套 navistate_landback_* / global_image_landback_*（就是上次导出的 78 张里的 landback 系列）。

1 · 两类东西的实现路径

项目高德怎么做的证据
矢量路口图 导航数据在路口段附带一段矢量十字数据；引擎把它解析成「进口车道中心线 → 转向连接曲线 → 出口车道」的折线，再按参数加粗描边、画箭头。 libGbl.so:
VectorCrossLayerItem::ShowVectorCross(const uint8_t*, int)
SegmentInfo::IsReqVectorCross()
真实路口拍照 同一路段若服务端有实景图，就下发 CrossImageInfo；HMI 收到 OnShowCrossImageHMI() 直接贴图，甚至可「只显示图」（IsOnlyShowCrossImage=1）不画矢量。 libGbl.so: bl::CrossImageInfo
libautonavi.so: CNaviComponentBase::OnShowCrossImageHMI()
MultipleScreen.json: IsOnlyShowCrossImage
显示开关/位置 按屏幕配置开图：CrossViewType 0/7 关/开，并给出宽高与左上角坐标。 MultipleScreen.json:
CrossViewType=7, CrossViewWidth=368, CrossViewHeight=276

注意配色差异：参数里写的是「半透明白底 + 白箭头」，而车机 9.5 实际显示是深色路面 + 黄色引导线。 说明这套 JSON 是「maneuver_render_style_0」的一种风格，实际主题由 MapTheme 覆盖。移植时按截图配色（深路 + 黄线）更贴近。

2 · 可交互原型

左图完全用 Canvas 按上面那套参数画（路宽 21、拐角圆滑、箭头 25），右卡是同一份车道数据的另一种表达。 换场景可以看引导线、车道箭头、方向卡怎么联动。

车道数3 推荐车道第 1 条 本车道第 1 条 车道 icon2, 0, 0

箭头样式取自包内 navistate_landback_*（白色模板）与 global_image_landback_*； 组合方向（直行+左转等）高德是位图直出，素材库只覆盖单方向，所以这里用同样的线宽/圆角规则矢量补画。

3 · 移植方案

  1. 车道箭头卡（先做，1 天级）。数据现成：AmapBroadcastHandlers 已经产出 LaneInfo(id, isRecommended, trafficLaneType)，id 就是 Back_icon。 新建一个 Composable：Row 里按 laneInfoList 铺 Image， 推荐车道用蓝色 tint / 高亮底。素材直接用上次导出的 zip。
  2. 路口放大图（简化版，2–3 天）。高德的矢量十字数据我们拿不到，但广播里有 laneInfoList（几条车道、各转哪）+ TBT icon（主转向）+ 距离，足够画示意路口： 按「进口车道数 × 转向」决定画十字/丁字/T 型，按 thick_width=21、corner_bessel 画黄色引导线。 用户看到的是「我要从第几条车道往哪拐」，信息量与高德接近。
  3. 真实路口拍照：不做。那是服务端图库，第三方拿不到 URL，协议里也没有对外的取图入口。 真想要可以自己拍 + 按坐标入库，但那是另一个项目。
  4. 数据缺口：进/出口车道数只能从 laneInfoList.size 推进口，出口车道数没有来源， 简化版固定按「出口 = 进口」画，或统一画 3 出。
