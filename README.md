Navipilot 是一款 Android 车机导航辅助 App，核心能力是把手机上的高德车机版投屏到同一局域网内的浏览器，例如特斯拉车机浏览器、平板浏览器或电脑浏览器。App 会在手机本地创建一个虚拟屏幕运行高德车机版，再把画面通过 HTTP 推送到浏览器，并支持浏览器触摸反控。

除了投屏，Navipilot 也可以连接 comma3 / openpilot 设备，把导航数据、车辆状态和红绿灯辅助信息联动起来，用于驾驶辅助场景。车道线识别由 comma3 端运行。

巡航按钮保留速度显示，点击打开选中 comma 设备的 `http://<IP>:7000` 网页；未选择设备时提示连接。首页高德红绿灯卡恢复原有信号展示，App 不运行手机端模型推理。

**7.2（versionCode 26100301）** 增加默认自动场景识别、左起第二车道偏好与7000实验几何展示，保留Release混淆。右侧显示本车道宽、左/右边界至路缘距离及“左起宽度带编号”，后者不是实际通行车道编号。5m与15m同纵向截面内插结果、概率/标准差、明确的非变道状态及不同连续帧通过检查才显示编号；缺失/过期/冻结/变道撤下。等宽假设无法排除路肩、应急车道或专用道，不能用于自动变道，不据此声称已定位本车。没有新增摄像头、本机推理或订阅；自动切换只改变路线提示，不开启驾驶控制。

首页左侧品牌卡下方增加模式选择与地图策略卡；右侧9个按钮/超车参数下方增加对应车端状态与边界卡，原高德、7000及7711分区不变。默认自动识别道路场景；至少3条不同有效高德10001广播跨越2秒才采用新场景，重复界面采样不算新广播。0进入高速、6进入高架/快速路、1-5/7-9进入常规；缺失/未知/过期/换路线立即回到待识别，变化期间不采用旧候选。手动点击任一模式会退出自动识别并保存选择，点击“自动识别”恢复；自动开关重启恢复，自动推断结果不作为下次启动的有效道路状态。请停车后操作手动选择。

| 模式 | 通行偏好 | 数据判定与优先级 |
|---|---|---|
| 高速 EAP | 默认左起第二条合法通行车道 | 高德实际 `ROAD_TYPE=0`；出口/分流推荐优先 |
| 高架 NOA | 默认左起第二条合法通行车道 | `ROAD_TYPE=6` 仅证明快速路，高架属性仍待驾驶员确认；出口/分流推荐优先 |
| 常规 NOO | 偏右侧合法通行车道 | 国省县乡道路及主要/次要/普通道路；路口转向推荐优先，排除专用/非机动车/停车车道需驾驶员确认 |

只在新鲜、路线一致、左右序号完整且推荐方向已识别的高德路口推荐组内排序候选。候选是路口地图提示，不是巡航目标车道，不定位本车，不发送变道指令。道路类别缺失不沿用旧值，不从默认 `roadType`、简化 `roadcate` 或7000刷新推断。失配、过期、停止/换导航源/换路线、车端报告偏航或接管/提示告警时撤下候选；未收到数据明确提示。高速2/3/4车道、高架2/3车道只是常见情况，不绘制成已测得车道，不假定最右一条是应急车道，也不假定高架没有应急车道。

**当前实现的是三种路线辅助场景，不是三种自动驾驶控制模式。** 切换只保存本机设置并取消旧待执行自动变道，不修改车端参数或发送 `LANECHANGE`、`SPEED`、转向命令；7000仍缺完整接管/故障/授权、后方间隙与合法车道信息，保持只读和既有安全门。横纵向激活仅展示车端状态。常规模式不自动处理红灯、路权、行人或路口转向；错过出口由驾驶员继续行驶并让地图重新规划，不强切多车道。EAP/NOA/NOO是场景名称，不是能力认证；“超越EAP、接近FSD”是研究目标，不是当前能力或安全承诺。本地 openpilot 分析与后续缺口见 `docs/highway_noa_eap_implementation_plan.md`。

设备连接信息中的HTTP等端口不用于UDP发送：命令、心跳和兼容目的地固定发送到选中设备的7706，避免把7000等发现端口误用为控制端口。

## 投屏适合哪些场景

- 特斯拉车机浏览器打开手机投屏地址，用车机屏幕查看手机地图。
- 车内平板、电脑或另一台手机通过浏览器查看并操作导航地图。
- 需要在车机大屏使用高德车机版，但车辆系统本身无法安装该 App。
- 希望导航投屏和 comma3 / openpilot 辅助信息共存，但两者也可以独立使用。

## 投屏工作原理

Navipilot 的投屏不是简单录制手机主屏幕，而是在手机内部创建一个独立的虚拟 Display。目标地图 App 会运行在这个虚拟屏上，因此投屏画面不会遮挡手机主界面，用户仍然可以在 Navipilot 首页查看状态和控制投屏。

```text
目标车机地图 App
  -> 特权虚拟 Display
  -> ImageReader 捕获画面
  -> JPEG / MJPEG 编码
  -> 手机本地 HTTP 服务 /stream
  -> 车机或其他设备浏览器显示

浏览器触摸 / 返回事件
  -> WebSocket /control
  -> ProjectionService
  -> 特权服务注入到虚拟 Display
  -> 地图 App 响应操作
```

### 1. 虚拟屏运行地图

App 通过 Shizuku 或 Stellar 授权启动特权服务，由特权服务创建虚拟 Display，并把高德车机版启动到该 Display 上。这样可以让地图在后台专用画布中运行，而不是占用手机当前屏幕。

### 2. 画面采集与编码

虚拟屏画面由 `ImageReader` 获取，编码后写入最新帧缓存。浏览器访问 `/stream` 时，App 持续输出 MJPEG 视频流。投屏页面右上角只显示简化后的帧率信息，方便判断当前画面是否流畅。

### 3. 浏览器反控

浏览器页面会监听 Pointer Events，把点击、拖动、抬手等事件转换为归一化坐标，通过 `/control` WebSocket 发回手机。手机端再把这些事件注入到虚拟 Display，目标地图 App 就会像被本地触摸一样响应。

### 4. 自适应浏览器窗口

浏览器打开页面后会回报窗口宽高、设备像素比和方向信息。App 根据这些信息调整虚拟屏参数，让投屏画面尽量贴合车机浏览器或横屏设备。

## 投屏使用步骤

1. 在手机上安装高德车机版。
2. 在手机实体屏幕上先打开一次目标地图，完成首次引导和定位权限授权。
3. 安装并启动 Shizuku 或 Stellar，完成授权。
4. 打开 Navipilot，进入“投屏”页面选择连接方式。
5. 未开通会员时点击“试用”，会员用户点击“投屏”。
6. 在车机浏览器或同一局域网设备浏览器中打开 App 显示的地址，例如 `http://192.168.31.92:8080/`。
7. 浏览器出现地图画面后，即可在浏览器上触摸操作地图。

如果 `8080` 打不开，可能是端口被占用或网络不可达。App 会自动尝试 `8081` 到 `8099`，请以 App 页面显示的最新地址为准，并确认手机和浏览器设备在同一局域网内。

## 试用与会员逻辑

- 未开通会员时，投屏页主按钮显示“试用”，每天累计可用 45 分钟。
- 当天试用额度用完后，投屏会自动停止，并跳转到会员页面。
- 会员用户首页主按钮显示“投屏”，点击后启动不限时投屏。
- 用户也可以随时点击“会员”按钮进入购买、恢复或设备迁移页面。
- 浏览器投屏成功后，底部推广信息只在试用状态显示；会员投屏不显示底部广告。

## 高德车机版回家 / 公司快捷导航

当投屏目标选择为高德车机版时，首页会显示“回家 / 导航 / 公司”滑动条。向左或向右滑动到阈值后，App 会调用高德车机版的一键导航广播：

```text
Action: AUTONAVI_STANDARD_BROADCAST_RECV
KEY_TYPE: 10040
DEST: 0 表示回家，1 表示公司
IS_START_NAVI: 0
```

这个功能依赖高德车机版自身保存的家和公司地址。Navipilot 不会保存或猜测用户地址，如果高德车机版未配置对应地址，应先在高德车机版中设置。

## comma3 / openpilot 连接能力

投屏功能可以独立使用，不要求连接 comma3。连接 comma3 后，Navipilot 会额外提供以下能力：

| 能力 | 说明 |
|---|---|
| 设备发现与连接 | 在局域网内发现 comma3，并连接 carrot server。 |
| 驾驶 HUD | 显示车速、限速、道路名称、转向、剩余里程等信息。 |
| 导航数据桥接 | 接收高德车机版广播，通过 WebSocket 7714 Navi v2 发送真实导航数据及失效状态。 |
| 路线数据 | 发送真实剩余距离/时间及已知总距离；广播没有完整折线时不伪造。旧7709/7712/7713发送已禁用。 |
| 实时车辆状态 | 通过 WebSocket 读取 `carState`、`modelV2`、`controlsState`、`deviceState` 等数据。 |
| 红绿灯辅助 | 显示信号灯、方向、倒计时和停车线距离等辅助信息。 |

CP搭子功能页始终显示驾驶 HUD 和红绿灯辅助卡片；设备未连接时，卡片会显示连接中的状态。

## comma3 数据链路原理

```text
高德车机版导航广播
  -> AmapBroadcastManager
  -> AmapBroadcastHandlers
  -> CarrotManFields
  -> NaviSourceTracker / NaviStreamManager
  -> WebSocket 7714 Navi v2
  -> comma3 / carrot server
```

`CarrotManFields` 是 App 内导航数据的共享状态；`NaviSourceTracker` 单独跟踪真实源的时间和位置，避免车端状态更新延续旧导航。`CarrotManNetworkClient.build7706Payload` 只构造基础时间包、显式命令包或目的地兼容包，不再发送旧导航正文。7000使用字段明确的 `/ws/compact_state` 子集；车端建议速度和归一化导航结果独立展示，不回灌为高德道路限速。

智能调速在距高速/高架匝道800米开始，以每档10km/h逐步降至60km/h；高德匝道40按用户策略纠正为60。档位根据剩余距离分配，每次更新最多调整10；晚发现或距离跳变时逐次追赶，不保证迟到数据已经完成出口前降速。主路升速需实际主路限速，弯道暂停升速、不暂停出口降速。此功能发送导航限速信息，最终车辆控制由carrot决定。

高德、腾讯等国内地图通常使用 GCJ-02 坐标，comma3 / openpilot 侧使用 WGS-84。App 在地图边界通过 `CoordinateConverter` 完成坐标转换，内部发往 comma3 的坐标保持 WGS-84。

## 通信端口

| 端口 / 协议 | 方向 | 用途 |
|---|---|---|
| HTTP / WebSocket 8080-8099 | 浏览器 ↔ App | 地图投屏、健康检查、触摸反控。 |
| UDP 7705 | comma3 → App | comma3 设备发现。 |
| UDP 7706 | App → comma3 | 心跳/时间、必要命令、目的地兼容信息。 |
| WebSocket 7714 | App → comma3 | Navi v2导航；28项目录、13 JSON流，缺失媒体不宣称可用。 |
| TCP 7709/7712、HTTP 7713 | — | App旧发送禁用；carrot仍实现这些接收端口。 |
| HTTP / WebSocket 7000 | App ↔ comma3 | 标准参数API和CVS1/CVB1 compact状态。 |
| TCP 7711 | 已移除 | App自7.9.12起不连接、不解析；不修改车端服务。 |

### 本地配置

```properties
sdk.dir=/path/to/Android/sdk

# 如需 Google 地图相关能力
MAPS_API_KEY=your_google_maps_api_key

# Release 签名
RELEASE_STORE_FILE=distribution.keystore
RELEASE_STORE_PASSWORD=your_keystore_password
RELEASE_KEY_ALIAS=your_key_alias

```

### 常用命令

```powershell
# Debug 构建
.\gradlew.bat assembleDebug

# Release 构建，需要 local.properties 中有签名配置
.\gradlew.bat assembleRelease

# 静态检查
.\gradlew.bat detekt

# 单元测试
.\gradlew.bat test

# 指定测试
.\gradlew.bat :app:testDebugUnitTest --tests "com.jixiexiaoge.drivingassist.SmartSpeedLimiterTest"

```

APK 默认输出到 `app\build\outputs\apk\debug\` 或 `app\build\outputs\apk\release\`。

Release使用`local.properties`中已有的RELEASE_*配置签名，开启R8代码混淆/优化和资源压缩，禁用调试，移除Android verbose/debug/info日志、保留警告和错误。第三方consumer规则及专用Shizuku反射入口保留规则保护运行兼容性，不使用整包keep或全局忽略缺失依赖。Debug不混淆，用于开发排错。签名私钥及`app\build\outputs\mapping\release\`中的mapping须私密保存，不和APK一起发布；mapping用于还原线上崩溃堆栈。

混淆只是提高逆向成本，并非代码/字符串/HTML资产加密，不能保证APK不可反编译或不能被复制。APK签名用于验证发布者及更新一致性，不防止反编译；敏感密钥、支付及授权的关键校验必须留在服务端，不依赖隐藏客户端代码实现安全。

## 隐私与安全

- 投屏画面和触摸事件默认只在用户局域网内传输。
- 车道线模型在手机本地推理，不上传道路相机画面。
- `local.properties`、签名密码、支付密钥、API Key、设备令牌等敏感配置不应提交到仓库。
- 车机浏览器访问投屏地址时，请确保连接的是可信局域网，避免在公共网络中暴露投屏服务。

## 贡献注意事项

- 投屏相关修改应保留 `/stream`、`/control`、`/health` 的兼容性。
- 不要让未选中的地图源覆盖共享导航状态。
- 高频高德广播应继续使用有界队列和单消费者处理，避免无界队列或一条广播一个协程。
- 修改导航字段时检查7714实际消费规则与源有效性；7706最小包不得触发旧导航块。
- 行为变更应补充聚焦单元测试，并运行相应 Gradle 检查。

本仓库未在根目录声明统一开源许可证。复用、分发或商用前，请确认仓库维护者以及地图 SDK、模型和第三方组件各自的许可条款。
